# vision/ – animal detection for the deterrent

Detects animals in a short burst of photos and tells you which way they're moving.
This folder only covers the YOLO side: collecting photos, labelling, training,
exporting, and one module (`detector.py`) your own code calls.
The motion sensor, deterrent and microcontroller logic are up to you.

| File | Runs on | What it does |
|---|---|---|
| `config.yaml` | – | **Your class list** and image size. Every script reads this. |
| `capture.py` | UNO Q / laptop | Takes photos when something moves (or every N seconds) |
| `get_example_images.py` | PC | Downloads ~15 public animal photos so you can test the pipeline today |
| `prelabel.py` | PC | Draws boxes automatically (YOLOE-26, works for any animal name) |
| `split_dataset.py` | PC | Builds the train/val folders YOLO wants |
| `train.py` | PC | Fine-tunes YOLO26n, exports it to NCNN for the UNO Q |
| `detector.py` | UNO Q | `AnimalDetector`: detections → animal + direction + approaching/leaving |
| `try_detector.py` | both | Runs the detector on folders or the live camera and prints speed |

```
data/raw/images/   photos (from capture.py)          <- you add
data/raw/labels/   one .txt per photo + classes.txt   <- prelabel.py, then you fix
data/dataset/      generated by split_dataset.py, don't edit
models/            animals.pt + animals_ncnn_model/   <- train.py
runs/              training plots, try_detector --save output
```

## Setup

**PC (training)**, Python 3.10+:
```bash
cd vision
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements-pc.txt
```

**UNO Q (running)**, over SSH or the board's terminal:
```bash
sudo apt install python3-venv git
cd vision
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-unoq.txt
ls /dev/video*            # your USB camera should show up as /dev/video0
```

## Try the whole pipeline in 5 minutes (example photos)

```bash
python get_example_images.py          # ~15 COCO photos of birds/cats/dogs
python prelabel.py --preview          # auto boxes; look at data/raw/preview/
python split_dataset.py
python train.py --epochs 3            # just to see it work; the model will be bad
python try_detector.py --images data/raw/images
```

## The real workflow

1. **Set your animals** in `config.yaml` (`classes:`). Use plain English names
   (`fox`, `heron`, `wild boar`). `prelabel.py` uses them as search prompts.
   Delete the example photos first: `rm data/raw/images/example_* data/raw/labels/example_*`.

2. **Collect photos** with the camera in its real spot, on the UNO Q:
   ```bash
   python capture.py --frames 5 --gap 0.4        # motion bursts, like the deterrent
   python capture.py --mode interval --every 120 # empty background shots, day AND night
   ```
   Copy `data/raw/images/` to the PC (scp, USB stick, shared drive).
   Phone or web photos of the same animals are also fine to add. Any filename works.

3. **Pre-label** on the PC: `python prelabel.py --preview`.
   It writes a label file for every new image and never overwrites existing ones.

4. **Fix the labels.** This is the step that decides how good the model will be.
   Use any tool that reads and writes YOLO `.txt` files, e.g.
   [X-AnyLabeling](https://github.com/CVHub520/X-AnyLabeling) (desktop) or Roboflow / CVAT (web):
   open `data/raw/images`, import YOLO labels from `data/raw/labels` with
   `data/raw/labels/classes.txt`, fix them, and export back as YOLO into `data/raw/labels`.
   Rules: box **every** animal in every image, tight around the body. Delete wrong boxes.
   A photo with no animal keeps an **empty** `.txt`, which teaches the model what's not an animal.

5. **Split and train** on the PC:
   ```bash
   python split_dataset.py
   python train.py                 # add --device 0 for an NVIDIA GPU
   ```
   Check `runs/animals*/` → `results.png` (mAP should go up), `confusion_matrix.png`, `val_batch0_pred.jpg`.

6. **Deploy:** copy `models/animals_ncnn_model/` to the same place on the UNO Q, then
   ```bash
   python try_detector.py --camera 0 --loop
   ```
   The first frame is slow because the model is warming up. Look at the ms/frame after that.

### How much data?
Start with **~100–200 labelled photos per animal**, plus about 10% empty backgrounds.
Include different times of day, weather and distances, and **IR night shots** if it has
to work at night. Then train, look at what it gets wrong, collect more of exactly that, and repeat.
Adding a class: append it to the END of `classes:`, label it, and retrain.

## Using it in your own code

Put your script in this folder (or add `vision/` to `PYTHONPATH`; in PyCharm,
right-click → *Mark Directory as → Sources Root*).

```python
import cv2
from detector import AnimalDetector

det = AnimalDetector()          # or AnimalDetector("yolo26n.pt", only=["cat", "dog", "bird"]) before training

frames = [...]                  # your burst: list of BGR images from cv2, or file paths
for a in det.analyze_burst(frames):
    print(a.name, a.direction, a.approach, a.confidence)
    # a.direction: left / right / up / down / still / unknown   (as seen in the picture)
    # a.approach:  approaching / leaving / same / unknown        (box getting bigger/smaller)
    # a.dx, a.dy:  movement in body lengths; a.boxes: per-frame Detection or None

# after the deterrent: take a few more frames
if det.is_gone(after_frames):   # True when the last 2 frames contain no animal
    ...
```

Useful knobs: `AnimalDetector(conf=0.4, move_threshold=0.25, max_jump=2.0)`. See the docstrings.

## Gotchas
- `imgsz` in `config.yaml` is used for training **and** on the board. If you change it, retrain or re-export.
- Frames from one burst are near-duplicates, so `split_dataset.py` keeps each burst in either
  train or val. This works through the `_b<burst>_f<frame>` filenames from `capture.py`.
- If wind or moving shadows keep triggering `capture.py`, raise `--sensitivity` (e.g. `0.03`).
- Training runs on the PC. Running inference on the UNO Q is fine; training there is not.
